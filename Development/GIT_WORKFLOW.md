
# Git Workflow

**Project:** ITH Attendance Management System

**Document Version:** 2.0

**Status:** Approved

---

# Purpose

This document defines the Git workflow used during project development.

---

# Repository Organization

The project consists of separate repositories for:

- Documentation
- Implementation

Documentation serves as the approved reference for implementation.

---

# Branching

Development should occur on feature branches.

The main branch should contain reviewed and approved work only.

---

# Commit Principles

Commits should:

- Represent a logical unit of work.
- Be focused on a single purpose.
- Avoid unrelated changes.

---

# Pull Requests

Pull requests should:

- Reference the implemented feature.
- Be reviewed before merging.
- Preserve backward compatibility where applicable.

---

# Merge Principles

Code should only be merged after:

- Documentation approval.
- Implementation review.
- Successful testing.
